Performance metrics split “the page is slow” into separate problems: slow content, delayed interaction, unstable layout, or slow server response. Each needs a different fix.

## Core Web Vitals first

Evaluate the 75th percentile (P75) of real visits and separate mobile from desktop traffic.

| Metric | Experience | Good | Needs improvement | Poor |
| --- | --- | ---: | ---: | ---: |
| LCP | Loading | ≤ 2.5 s | 2.5–4 s | > 4 s |
| INP | Responsiveness | ≤ 200 ms | 200–500 ms | > 500 ms |
| CLS | Visual stability | ≤ 0.1 | 0.1–0.25 | > 0.25 |

## LCP: when does the main content appear?

Largest Contentful Paint measures when the largest visible content element finishes rendering. For a high LCP, inspect hero images, render-blocking CSS/fonts/scripts, TTFB, client-side rendering dependencies, CDN placement, and caching.

## INP: does interaction respond promptly?

Interaction to Next Paint measures the delay from a click, tap, or key press to the next visual update. Inspect tasks longer than 50 ms, synchronous computation, large component-tree updates, and third-party scripts. Split work, defer non-critical work, or use a Web Worker where appropriate.

## CLS: does the page shift unexpectedly?

Cumulative Layout Shift measures unexpected movement. Reserve dimensions for images, video, and iframes; avoid inserting asynchronous content above existing content; control web-font swaps; and animate with `transform`.

## FCP, TTFB, TBT, DCL, and Load

- **FCP:** first text, image, Canvas, or SVG paint; a P75 up to 1.8 seconds is a useful target.
- **TTFB:** request start to first response byte, including network and server time; up to 0.8 seconds is a useful target.
- **TBT:** total portion of loading tasks beyond 50 ms; lower is better.
- **DOMContentLoaded:** HTML parsing and deferred-script execution completed.
- **Load:** the page and dependent resources finished loading.

## Interpret the data correctly

1. Prefer percentiles and distributions over averages alone.
2. Separate mobile from desktop and compare individual pages.
3. Correlate performance with releases, traffic, and error changes.
4. A missing metric is not zero; Performance API support varies by browser.

::note
TraceVista collects directly from native browser Performance APIs. Sampling, browser coverage, and aggregation can differ from other platforms. Use it for trends within TraceVista instead of mechanically comparing one number across tools.
::
