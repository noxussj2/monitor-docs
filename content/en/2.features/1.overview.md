PulseWatch divides web monitoring into four complementary data streams. They share website and page-view context, so you can follow an anomaly to the related page, runtime environment, and user activity.

## Traffic analytics

Every page load or SPA route change creates a visit record. Reports include current and total PV/UV, trends, popular pages, referrers, country or region, device, browser, operating system, language, time zone, and network type. [Explore traffic analytics →](/features/analytics)

## Performance monitoring

The SDK uses browser Performance APIs to observe loading, interaction, visual stability, and main-thread blocking. It reports LCP, INP, CLS, FCP, TTFB, TBT, DOMContentLoaded, and Load. [Understand performance metrics →](/features/performance)

## Error monitoring

PulseWatch automatically captures JavaScript runtime exceptions, unhandled Promise rejections, resource failures, Fetch/XHR network errors, and HTTP 4xx/5xx responses. Records include page context, stack traces, and recent breadcrumbs. [Review error collection →](/features/errors)

## Business events

Business events are **never generated automatically**. They appear only when your code calls `track()`:

```js
window.PulseWatch.track('checkout_completed', {
    order_type: 'subscription',
    plan: 'professional'
})
```

Visitor, session, page-view, URL, and path context is attached automatically.

::tip
Start with three to five events that genuinely affect product decisions, such as completed signup, completed purchase, and search with no results. Consistent naming matters more than event volume.
::

## From discovery to validation

1. **Discover** an unusual trend, error, or performance distribution.
2. **Narrow** it to a page, environment, version, or error type.
3. **Assess** impact using traffic and business events.
4. **Fix** the resource, code, API, or layout.
5. **Validate** with before-and-after real-user data.
