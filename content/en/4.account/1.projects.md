A monitored website is TraceVista’s unit for data isolation, ownership, and ingestion accounting. It normally represents one production site or independently deployed environment.

## How to separate websites

Create separate monitored websites for production, staging, and testing; independent products or domains; or business lines that need separate usage and trends. Do not create one per page—page paths are already part of visit and performance records.

::note
A Free account can add **1 monitored website**. A PRO account can add **10 monitored websites**.
::

## Domain format

Enter only a hostname such as `app.example.com`. Do not include `https://`, a port, path, or query string.

The server extracts the hostname from `Origin`, falling back to `Referer`, and requires an exact match with the bound domain. Matching is case-insensitive and ignores protocol, port, and a trailing dot, but does not automatically include `www` or other subdomains:

- `example.com` matches only `example.com`
- `www.example.com` matches only `www.example.com`
- `app.example.com` matches only `app.example.com`
- `example.com` and `www.example.com` do not match each other
- `https://app.example.com:8443` matches `app.example.com`

A missing or invalid source also fails validation. Create separate websites and Keys for multiple hostnames or environments.

::warning
On localhost or 127.0.0.1, the hostname does not match the domain bound to the API Key, so reports return 403. This is expected domain validation, not an SDK failure.
::

## API Keys and website changes

Each website has a separate API Key submitted through `X-API-Key`. The Key may appear in frontend code, but it is not a Console login secret. Changing the website name or domain does not change the Key, migrate data, or delete history.

## Clear data, ingestion switches, and deletion

**Clear data** deletes visits, business events, performance metrics, and errors but keeps the website, domain, and API Key. It does not return used monthly quota.

When a data type is disabled in website settings, the server ignores it and does not count it toward usage. Deleting the website removes its settings and API Key; old SDK code on the page can no longer report.
