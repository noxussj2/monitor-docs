Each Free account receives **200 MB of context-data ingestion** and **3,000 events per calendar month** and can monitor one website. PRO monitors up to ten websites and includes **1 GB of context data** and **30,000 events per month**.

## Accounting period

Usage follows calendar months in China Standard Time, from 00:00 on the first day to 00:00 on the first day of the next month. Counters restart each month.

## What counts as an event

Successful server records across page visits (`page_views`), business events (`events`), frontend errors (`errors`), and performance metrics (`web_vitals`) count together.

## What counts as context data

Only the final stored `data` field counts: `events.data` includes the second argument to `track(name, data)` and its `_pulsewatch` context; `errors.data` includes stacks, page context, breadcrumbs, and extra details.

Structural fields such as URL, title, visitor ID, device, region, referrer, metric values, event name, path, error type, and server time do not count. Objects and arrays are serialized to JSON and measured in UTF-8 bytes.

One `data` value is limited to about 5 MiB. Above that limit, the original value is discarded and replaced with a short limit message, whose bytes count toward usage.

## When a limit is reached

1. New SDK reports return `429`, and the SDK on that page stops sending.
2. Historical data, website settings, and API Keys remain.
3. Ingestion resumes in the next calendar month or after upgrading to PRO.
4. Overage never triggers an automatic charge.

## Deleting data does not restore quota

Deleting history and reports does not return monthly usage. If 180 MB has been used, deleting records still leaves about 20 MB for that month. Counters restart only in the next calendar month.

## Review and reduce usage

The Console shows used, total, and remaining context data and events, plus each website’s usage. Near the limit, check for error storms, duplicate events, and test environments using a production Key.

Keep only valuable events, avoid complete objects and large text, separate test environments, fix repeated errors, do not load the SDK twice, and disable unneeded data types. The SDK also limits one client to 60 reports per minute, suppresses identical errors for three seconds, and safely serializes data.
