This guide uses a Script tag for the shortest setup. It works with plain HTML, Vue, Nuxt, React, and single-page applications that use the History API.

## Before you start

- An accessible web application domain
- A PulseWatch Console account
- Permission to edit the page HTML or application template

## 1. Add a monitored website

Sign in to the Console, choose **Add website**, and enter a name and domain. Enter only a hostname such as `shop.example.com`—no protocol, port, or path.

The domain must exactly match the hostname users open. Protocol and port are ignored, but `example.com`, `www.example.com`, and `shop.example.com` are three different hostnames. Reports from another domain, local `localhost`, or a preview URL return 403.

::warning
On localhost or 127.0.0.1, the hostname does not match the domain bound to the API Key, so reports return 403. This is expected domain validation, not an SDK failure.
::

After creating the website, copy its API Key, such as `mk_your_project_key`.

::warning
The API Key is used for browser reporting and may appear in frontend code. Never put a login token or server credential in the SDK configuration.
::

## 2. Install the SDK

Place the snippet from the Console in the page `<head>`:

```html
<script
    defer
    src="https://apm.noxussj.top/monitor.min.js"
    data-project-key="mk_your_project_key">
</script>
```

Replace the example API Key. In Nuxt, add the same script attributes under `app.head.script` in `nuxt.config.ts`; use runtime configuration or deployment variables for environment-specific Keys.

## 3. Generate test data

1. Open a page that includes the SDK.
2. Navigate to another page once.
3. Confirm in browser developer tools that the SDK file loaded.
4. Return to the PulseWatch Console and refresh the website data.

Visit data normally appears first. Performance data is submitted when the page is hidden or unloaded, or about 10 seconds after SDK startup.

## 4. Record your first business event

```js
const accepted = await window.PulseWatch.track('signup_completed', {
    plan: 'free',
    source: 'homepage'
})
```

The `Promise<boolean>` resolves to `true` when the API accepts the report. `false` means the SDK was not started, the report was rate-limited, quota was exhausted, or the request failed.

## Integration checklist

- [ ] Production uses the production website’s API Key
- [ ] The bound domain exactly matches the page `Origin` hostname
- [ ] The SDK loads over HTTPS and is installed only once
- [ ] CSP permits the SDK and monitoring API
- [ ] Test events contain no passwords, tokens, phone numbers, or other sensitive data
- [ ] The Console shows visit, performance, or error data

## No data?

Add `data-debug="true"` to the Script, then inspect Console and Network. For a 403, open the request **Response**. `APIKEY does not match the current website domain` means the bound domain differs from `Origin` (or `Referer` when Origin is absent). Check `www`, subdomains, localhost, preview domains, and whether the page uses another website’s API Key. See [API Key and bound domains](/en/sdk/installation#api-key-and-bound-domain).
