PulseWatch is a **Real User Monitoring (RUM)** platform for web applications. A lightweight Browser SDK automatically collects visits, performance, and error data. It also records the business events you explicitly send with `track()`, organizing every signal into product data you can query and compare.

It goes beyond “is the server online?” and answers questions closer to the actual user experience:

- Did the page open successfully, and how long did its main content take to appear?
- Did clicks, input, and route changes respond promptly?
- Did the layout shift, a resource fail, or an API return an error?
- Which pages, browsers, devices, and users were affected?
- Did the real experience improve after a fix was released?

## Why real-user monitoring matters

Local development, automated tests, and Lighthouse are important, but they usually run in controlled conditions. Real users may have entry-level phones, weak networks, older browsers, or connect from different regions. Field data is the only way to see those differences.

| Signal | Question answered | Common uses |
| --- | --- | --- |
| Page visit | Who visited which page and when? | PV/UV, trends, referrers, popular pages |
| Performance | How long until content and interactions were ready? | Find slow pages and rendering or main-thread bottlenecks |
| Frontend error | What failed in the browser? | Fix JS, Promise, resource, and API errors |
| Business event | Did the user complete an important action? | Track signup, purchase, search, and submission flows |

## How it works

::steps
### Add a monitored website

Add the website in the Console with its name and production domain. PulseWatch creates a separate API Key for it.

### Install the SDK

Place a Script containing `data-project-key` in the page. Automatic collection starts without individual performance listeners.

### Observe real data

Visit the site. Visits, performance, errors, and events begin appearing in the Console.

### Improve and validate

Fix high-impact, frequent problems first, then watch the same metric after release to validate the result.
::

## Core capabilities

::card-group
  :::card{icon="i-lucide-chart-no-axes-combined" title="Traffic analytics" to="/features/analytics"}
  Explore PV, UV, trends, locations, referrers, devices, browsers, and popular pages.
  :::
  :::card{icon="i-lucide-gauge" title="Performance monitoring" to="/features/performance"}
  Collect LCP, CLS, INP, FCP, TTFB, TBT, DCL, and Load.
  :::
  :::card{icon="i-lucide-bug" title="Error monitoring" to="/features/errors"}
  Capture runtime, Promise, resource-loading, and API errors automatically.
  :::
  :::card{icon="i-lucide-mouse-pointer-click" title="Event tracking" to="/features/analytics#business-events"}
  Use `track()` to connect key business actions with the current page context.
  :::
::

::note
PulseWatch focuses on the real browser experience. It does not replace server-side APM, infrastructure monitoring, or logs. Use them together to trace a user-visible symptom to its frontend or backend cause.
::
