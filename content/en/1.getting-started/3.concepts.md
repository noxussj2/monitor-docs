## Monitored websites and API Keys

A **monitored website** is the basic unit for data isolation and ingestion accounting. It usually represents one production site or one environment. Each website has its own domain, API Key, and monthly usage. A Free account can add one website.

The **API Key** travels with SDK requests and assigns data to the correct website. It is not a Console login credential. Apart from the public PV/UV overview, it cannot read full monitoring data or change settings.

## Visitors, sessions, and page views

| Concept | Stored in | Changes when | Purpose |
| --- | --- | --- | --- |
| Visitor `visitor_id` | `localStorage` | Local storage is cleared or unavailable | Estimate unique visitors (UV) |
| Session `session_id` | `sessionStorage` | A new tab or session storage is created | Connect activity in one browser session |
| Page view `page_view_id` | Memory | Initial load and each SPA route change | Connect performance, events, and errors to the current page |

These are random technical identifiers, not authenticated user IDs. PulseWatch does not know a visitor’s real name, account, or contact details by default.

## Four monitoring data types

- **Page visits:** URL, path, title, referrer, viewport, screen, language, time zone, network information, navigation type, and SDK version.
- **Performance:** LCP, CLS, INP, FCP, TTFB, TBT, DOMContentLoaded, and Load. Browser support varies, so one visit may not contain every metric.
- **Errors:** Type, message, stack, current visit context, recent breadcrumbs, and developer-supplied details.
- **Business events:** Explicitly reported by website code through `PulseWatch.track()`, with current visit context added automatically.

## Ingestion quota

A Free account can monitor one website and receives 200 MB of context data plus 3,000 events per calendar month. New data stops after either limit is reached, but history and website settings remain. Deleting history does not return used quota.
