---
title: Privacy, Security, and Collection Boundaries
description: Understand what the SDK does and does not collect by default, and your responsibility for custom data.
---

PulseWatch follows data minimization: it collects only technical information needed to analyze page experience by default and does not read input values, cookies, or page content. Integrators must still assess privacy requirements and provide notices appropriate to their region, users, and applicable law.

## Collected by default

- Page URL, path, title, and referrer
- Random visitor, session, and page-view identifiers
- Viewport, screen, language, time zone, and limited network capabilities
- Durations exposed by browser Performance APIs
- JavaScript, Promise, resource, and API error information
- Clicked element tag, ID, and up to two classes
- SDK version and navigation type

## Not collected by default

- Input and form values or passwords
- Cookies, login tokens, or authorization headers
- Page content, full DOM, or clicked element text

Monitoring requests use `credentials: 'omit'`, so they do not intentionally carry the website’s cookies.

## Responsibility for custom data

Your code controls event data passed to `track()` and extra details passed to `captureError()`. Use an allowlist of fields. Never pass a complete user object, form, request headers, or unfiltered backend response.

```js
window.PulseWatch.track('checkout_failed', {
    payment_method: 'card',
    reason_code: 'issuer_declined'
})
```

If consent is required, load or initialize the SDK only after consent. Prevent future initialization when consent is withdrawn. Withdrawal does not automatically delete previously submitted data or the browser-local visitor identifier.
