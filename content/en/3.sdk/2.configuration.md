---
title: SDK Configuration
description: Configure projectKey, apiBase, debug, and autoTrack, including multi-environment and CSP guidance.
---

The SDK prefers Script `data-*` attributes. Use global `PulseWatchConfig` when configuration must be injected before the script loads. A few advanced integrations can pass options to `PulseWatch.init()`.

## Options

| Option | Script attribute | Type | Default | Description |
| --- | --- | --- | --- | --- |
| `projectKey` | `data-project-key` | `string` | Empty | Required; identifies the monitored website |
| `apiBase` | `data-api-base` | `string` | SDK script origin | Custom monitoring API base URL |
| `debug` | `data-debug` | `boolean` | `false` | Print diagnostics in browser Console |
| `autoTrack` | `data-auto-track` | `boolean` | `true` | Record page visits automatically |

## Debug mode

Add `data-debug="true"` to the Script. Messages begin with `[PulseWatch]` and show startup context and reporting failures. Disable it in production after diagnosis to avoid Console noise.

## Disable automatic visit tracking

Set `data-auto-track="false"`. Performance and error listeners remain active, and public methods such as `track()` and `captureError()` still work. The current SDK has no separate manual page-view API, so keep automatic tracking unless you need only errors or business events.

## Custom API base URL

```js
window.PulseWatch.init({
    projectKey: 'mk_your_project_key',
    apiBase: 'https://monitor-api.example.com'
})
```

The API must permit CORS from the website and accept the `Content-Type` and `X-API-Key` headers.

## Multiple environments and CSP

Create separate websites and API Keys for production, staging, and testing. If the website uses CSP, allow at least:

```text
script-src https://apm.noxussj.top
connect-src https://apm.noxussj.top
```

Merge these sources into the existing policy; do not replace the whole CSP.
