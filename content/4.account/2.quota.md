当前每个免费账号默认拥有**每个自然月 200 MB 上下文 data 接收量**和**3000 次事件触发额度**。免费账号可监控 1 个网站；PRO 账号可监控 10 个网站，并提供每月 **1 GB 上下文 data 接收量**和 **30000 次事件触发额度**。

## 统计周期

接收量按北京时间自然月统计：从每月 1 日 00:00 到下月 1 日 00:00。进入新的自然月后，新接收量从零重新累计。

## 哪些数据计入事件次数

以下四类被服务端接受的监控数据，都会共同计入账号事件触发次数：

- 页面访问 `page_views`
- 业务事件 `events`
- 前端错误 `errors`
- 性能指标 `web_vitals`

事件触发次数按服务端成功接收的记录次数累计，四类事件合并计算，先达到账号月度次数上限即停止接收新数据。

## 哪些 data 计入接收量

上下文 data 接收量只统计最终落库的 `data` 字段内容：

- 埋点事件 `events.data`：SDK `track(name, data)` 的第二个参数，包含 SDK 自动追加的 `_pulsewatch` 上下文。
- 错误事件 `errors.data`：SDK 采集的错误上下文，例如错误栈、页面上下文、面包屑、额外信息等。

以下内容不计入上下文 data 接收量：

- 访问统计字段，例如 URL、标题、访客 ID、设备、浏览器、地区、来源等。
- 性能指标字段，例如 LCP、CLS、INP、FCP、TTFB 等数值。
- 埋点事件名、路径、错误类型、错误消息、服务端时间、项目 ID 等结构字段。

计算规则：服务端先将 `data` 规范化为字符串；对象和数组会序列化为 JSON 字符串，字符串保持原样，空值按 0 字节计算；然后按 UTF-8 字节数累计到账号本月上下文 data 接收量。

单次上报的 `data` 最大约 5 MiB。超过限制时，服务端会丢弃原始 `data`，只保存 `当前 data 超出限制`，本次 data 接收量按这段提示文本计算。

## 达到额度上限后

账号达到当月上下文 data 接收量或事件触发次数任一上限后：

1. 服务端对新的 SDK 上报返回 `429`。
2. 当前页面中的 SDK 停止继续发送监控数据。
3. 已有历史数据、网站配置和 API Key 保留。
4. 新自然月开始或升级 PRO 后可以继续接收数据。

平台不会因为超量自动扣费。

## 清空数据不会恢复接收量

手动清空监控数据只会删除历史记录和报表展示，不会返还当月已经使用的接收量。

例如：某个免费账号本月已经接收 180 MB 上下文 data，即使清空历史记录，本月仍只剩约 20 MB 可接收量。下个自然月开始后，免费接收量和触发次数才会重新计算。

## 查看用量

控制台提供账号总览和网站明细：

- 账号已使用上下文 data 字节数
- 账号总上下文 data 接收量
- 账号剩余上下文 data 接收量
- 已使用事件触发次数
- 剩余事件触发次数
- 每个网站实际占用的 data 和事件次数
- 当前统计周期

建议在额度接近上限前检查是否存在错误风暴、重复事件或测试环境误用生产 Key。

## 关闭不需要的数据接收

可以在管理端的网站设置中关闭以下功能：

- 访问统计
- 埋点事件
- 性能监控
- 错误监控

关闭后，服务端不接收对应类型的数据，也不会计入接收量和事件触发次数。你可以临时关闭低优先级监控来节省额度。

## 降低接收量消耗的方法

- 只记录会影响产品判断的业务事件
- 避免在事件中传递完整对象或大段文本
- 为测试环境添加独立监控网站
- 修复短时间大量重复出现的错误
- 不要在页面中重复加载 SDK
- 不需要访问分析、性能、错误或埋点时，在管理端关闭对应数据接收开关

SDK 已内置单客户端每分钟最多 60 次上报、相同错误 3 秒抑制和数据安全序列化，但这些机制不能替代良好的事件设计。
