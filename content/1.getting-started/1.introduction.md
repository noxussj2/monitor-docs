PulseWatch 是一个面向 Web 应用的**真实用户监控平台**（Real User Monitoring，简称 RUM）。它通过运行在用户浏览器中的轻量 SDK，持续记录访问、性能、错误和关键业务事件，再把这些信号组织成可查询、可比较的产品数据。

它要回答的不是“服务器是否在线”这一个问题，而是更接近真实体验的几个问题：

- 用户有没有顺利打开页面，主要内容多久出现？
- 点击、输入和路由切换是否及时响应？
- 页面有没有意外跳动、资源加载失败或接口报错？
- 问题影响哪些页面、浏览器、设备和用户？
- 修复上线以后，真实用户体验是否确实变好了？

## 为什么需要真实用户监控

本地开发、自动化测试和 Lighthouse 很重要，但它们通常发生在可控环境里。真实用户可能使用低端手机、弱网、旧浏览器，也可能从不同地区访问。只有在真实访问现场采集的数据，才能反映这些差异。

PulseWatch 将一次访问拆成多种相互关联的信号：

| 信号 | 解决的问题 | 常见用途 |
| --- | --- | --- |
| 页面访问 | 谁在什么时候访问了什么页面 | PV/UV、趋势、来源、热门页面 |
| 性能指标 | 用户看到内容和完成交互用了多久 | 找慢页面、定位加载或主线程瓶颈 |
| 前端错误 | 浏览器里发生了哪些失败 | 修复 JS、Promise、资源和接口错误 |
| 业务事件 | 用户是否完成了关键动作 | 追踪注册、购买、搜索、提交等行为 |

## 平台如何工作

::steps
### 创建项目

在控制台填写项目名称和正式域名。平台为项目生成独立的网站 Key，用来识别上报数据。

### 安装 SDK

将一段带有 `data-project-key` 的 Script 放到页面中。SDK 会自动开始采集，无需逐个配置性能监听器。

### 观察真实数据

访问网站后，控制台会逐步出现访问、性能、错误和事件数据。可以按页面、环境和时间趋势判断影响范围。

### 优化并验证

根据数据选择优先级，修复影响大、频率高的问题；上线后继续观察同一指标，确认优化结果。
::

## 适合谁使用

- 希望建立前端质量基线的开发团队
- 需要定位线上白屏、加载慢和交互卡顿的产品团队
- 同时关心技术体验和注册、转化等业务结果的运营团队
- 维护多个 Web 项目，希望用统一方式观察质量的组织

::note
PulseWatch 关注浏览器端真实用户体验，它不能替代服务端 APM、基础设施监控和日志系统。将它们结合使用，可以从用户现象追踪到前后端根因。
::
