本指南使用 Script 標籤完成最短接入，適用於一般 HTML、Vue、Nuxt、React 及使用 History API 的單頁應用程式。

## 準備工作

- 一個可瀏覽的 Web 應用程式域名
- PulseWatch 管理後台帳戶
- 修改頁面 HTML 或應用程式範本的權限

## 1. 新增監控網站

登入管理後台，選擇「新增網站」，填寫網站名稱及網站域名。域名只填 `shop.example.com`，不要包含協定、連接埠或路徑。

網站域名必須與用戶實際開啟頁面時的 hostname 完全一致。協定和連接埠不參與比較，但 `example.com`、`www.example.com` 和 `shop.example.com` 會視為三個不同域名。由其他域名、本機 `localhost` 或預覽地址上報會返回 403。

::warning
本機使用 localhost 或 127.0.0.1 時，hostname 與 API Key 綁定域名不一致，上報會返回 403。這是正常的域名校驗，並非 SDK 故障。
::

新增後複製網站的 API Key，例如 `mk_your_project_key`。

::warning
API Key 用於瀏覽器資料上報，可以出現在前端頁面；登入 Token 及伺服器端憑證絕不能放進 SDK 設定。
::

## 2. 安裝 SDK

把管理後台提供的程式碼放在頁面 `<head>` 中：

```html
<script
    defer
    src="https://apm.noxussj.top/monitor.min.js"
    data-project-key="mk_your_project_key">
</script>
```

請替換示例 API Key。Nuxt 可在 `nuxt.config.ts` 的 `app.head.script` 中加入同一組屬性，並以運行時設定或部署變數管理不同環境的 Key。

## 3. 產生驗證資料

1. 開啟一個已安裝 SDK 的頁面。
2. 在頁面之間跳轉一次。
3. 在瀏覽器開發者工具確認 SDK 檔案載入成功。
4. 返回 PulseWatch 管理後台重新整理資料。

瀏覽資料通常先出現；效能資料會在頁面隱藏、卸載，或 SDK 啟動約 10 秒後提交。

## 4. 記錄第一個業務事件

```js
const accepted = await window.PulseWatch.track('signup_completed', {
    plan: 'free',
    source: 'homepage'
})
```

`Promise<boolean>` 返回 `true` 表示介面已接受本次上報；`false` 表示未啟動、被限流、額度已用完或請求失敗。

## 接入檢查清單

- [ ] 正式環境使用正式網站的 API Key
- [ ] 綁定域名與頁面 `Origin` 的 hostname 完全一致
- [ ] SDK 可透過 HTTPS 正常載入，且頁面沒有重複安裝
- [ ] CSP 允許載入 SDK 並連接監控介面
- [ ] 測試事件不含密碼、Token、電話等敏感資料
- [ ] 管理後台可看見瀏覽、效能或錯誤資料

## 看不到資料？

在 Script 加入 `data-debug="true"`，再查看 Console 及 Network。若上報返回 403，開啟請求的 **Response**；`APIKEY 與當前網站域名不匹配` 表示綁定域名與 `Origin`（缺失時使用 `Referer`）不一致。重點檢查 `www`、子域名、本機地址，以及是否誤用了其他網站的 API Key。詳情見 [API Key 與綁定域名](/zh-MO/sdk/installation#api-key-與綁定域名)。
