效能指標把「頁面很慢」拆成可獨立分析的問題：內容顯示緩慢、點擊回應緩慢、版面不穩定或伺服器回應緩慢，各自需要不同方法。

## 核心 Web 指標

以真實瀏覽的第 75 百分位（P75）評估，並分開查看流動裝置與桌面裝置。

| 指標 | 體驗維度 | 良好 | 需要改善 | 較差 |
| --- | --- | ---: | ---: | ---: |
| LCP | 載入效能 | ≤ 2.5 秒 | 2.5～4 秒 | > 4 秒 |
| INP | 互動回應 | ≤ 200 毫秒 | 200～500 毫秒 | > 500 毫秒 |
| CLS | 視覺穩定性 | ≤ 0.1 | 0.1～0.25 | > 0.25 |

## LCP：主要內容多久顯示

Largest Contentful Paint 是視窗中最大內容元素完成渲染的時間。數值偏高時，檢查首屏圖片、關鍵 CSS/字型/Script、TTFB、客戶端渲染依賴、CDN 和快取。

## INP：互動是否及時回應

Interaction to Next Paint 衡量點擊、觸控或鍵盤互動至下一次視覺更新的延遲。檢查超過 50 毫秒的長任務、同步計算、過大的元件樹更新、第三方 Script，並考慮拆分工作或 Web Worker。

## CLS：頁面是否意外跳動

Cumulative Layout Shift 衡量意外版面移動。為圖片、影片和 iframe 預留尺寸；避免在既有內容上方插入非同步內容；控制 Web Font 及使用 `transform` 動畫。

## FCP、TTFB、TBT、DCL 與 Load

- **FCP**：首次繪製文字、圖片、Canvas 或 SVG 的時間；P75 建議不超過 1.8 秒。
- **TTFB**：由請求開始至收到首位元組，包含網絡及伺服器處理；0.8 秒內可作良好參考。
- **TBT**：載入期間長任務超過 50 毫秒的阻塞部分總和，越低越好。
- **DOMContentLoaded**：HTML 解析及延遲 Script 執行完成。
- **Load**：頁面及依賴資源載入完成。

## 正確解讀資料

1. 優先查看分位數和分佈，而非只有平均值。
2. 分開判斷流動裝置與桌面裝置，並按頁面比較。
3. 把效能變化與版本發佈、瀏覽量及錯誤變化一同分析。
4. 缺失指標不等於零；瀏覽器對 Performance API 的支援不同。

::note
TraceVista 使用瀏覽器原生 Performance API。樣本、瀏覽器覆蓋及聚合方式可能與其他平台不同，適合觀察平台內的真實趨勢，不宜機械地逐項比較單一數值。
::
