PulseWatch 把 Web 應用程式監控分成四條互相補充的資料鏈路。它們共享網站及頁面瀏覽內容，讓你由異常現象追蹤相關頁面、運行環境和用戶行為。

## 瀏覽分析

每次開啟頁面或 SPA 路由變更都會形成一筆瀏覽記錄，包括今日及累計 PV/UV、時間趨勢、熱門頁面、來源、國家或地區、裝置、瀏覽器、作業系統、語言、時區及網絡類型等。[了解瀏覽分析 →](/features/analytics)

## 效能監控

SDK 使用瀏覽器 Performance API 觀察載入、互動、視覺穩定性及主執行緒阻塞，提交 LCP、INP、CLS、FCP、TTFB、TBT、DOMContentLoaded 及 Load。[了解效能指標 →](/features/performance)

## 錯誤監控

平台自動擷取 JavaScript 運行時異常、未處理 Promise 拒絕、資源載入失敗，以及 Fetch/XHR 網絡錯誤和 HTTP 4xx/5xx。記錄包括頁面內容、堆疊及最近行為麵包屑。[了解錯誤邊界 →](/features/errors)

## 業務事件

業務事件**不會自動產生**；只有網站主動呼叫 `track()` 才會記錄：

```js
window.PulseWatch.track('checkout_completed', {
    order_type: 'subscription',
    plan: 'professional'
})
```

事件會自動附加訪客、工作階段、頁面瀏覽、URL 及路徑內容。

::tip
先從 3 至 5 個真正影響業務判斷的事件開始，例如完成註冊、完成購買及搜尋無結果。清晰一致的命名比事件數量更重要。
::

## 從發現到驗證

1. **發現**趨勢、錯誤或效能分佈異常。
2. **定位**至頁面、環境、版本或錯誤類型。
3. **評估**瀏覽量和業務影響。
4. **修正**資源、程式碼、介面或版面。
5. **驗證**改動前後的真實用戶資料。
