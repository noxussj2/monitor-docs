访问分析描述用户如何进入和浏览网站，业务事件描述用户是否完成产品中的关键动作。两者结合，才能把体验质量和业务结果联系起来。

## 页面访问数据

SDK 自动记录页面 URL、标题、来源、访客与会话标识，并补充：

- 视口和屏幕尺寸、设备像素比
- 语言、时区
- 导航类型
- 网络有效类型、往返时延、下行速度和省流模式（浏览器支持时）
- SDK 版本

## PV、UV 与会话

- **PV**：页面访问次数。SPA 的有效路由变化也会产生新的页面访问。
- **UV**：按浏览器本地访客标识估算的独立访客数。
- **会话**：同一标签页会话存储范围内的一组访问。

UV 是技术标识下的估算值。用户清理本地存储、更换浏览器或设备后会形成新的访客标识；不同设备也不会自动合并为同一个人。

## SPA 自动追踪

SDK 会监听 `history.pushState`、`history.replaceState` 和 `popstate`。URL 发生变化时，它会：

1. 提交上一页面已经采集的性能指标。
2. 创建新的 `page_view_id`。
3. 记录新的页面访问和来源关系。

如果你的应用只改变页面内容而不改变 URL，需要主动设计业务事件，或让路由产生可区分的路径。

## 业务事件

业务事件**不会自动采集**。平台无法猜测哪些动作对你的产品重要，需要你在代码中明确调用 `track()` 来触发：

```js
window.PulseWatch.track('search_submitted', {
  result_count: 18,
  category: 'docs'
})
```

也可以指定自定义页面路径：

```js
window.PulseWatch.track(
  'checkout_completed',
  { order_type: 'subscription' },
  { path: '/checkout/success' }
)
```

事件名称最长 100 个字符，自定义数据序列化后建议不超过 10 KB。

## 命名建议

推荐使用稳定的 `对象_动作` 格式和小写下划线：

```text
signup_started
signup_completed
search_submitted
checkout_completed
report_exported
```

避免把按钮文案、页面标题或时间戳写进事件名。变化的信息应该放在事件数据中，这样事件才容易聚合。

::warning
自定义事件内容由接入方决定。请不要上报密码、Cookie、访问 Token、银行卡、完整身份证件、医疗信息或其他不必要的个人敏感信息。
::
