---
title: 功能总览
description: 从访问、性能、错误和业务事件四个角度，了解 PulseWatch 如何呈现完整的用户体验。
---

PulseWatch 将 Web 应用监控分成四条互相补充的数据链路。它们共享网站和页面访问上下文，因此可以从一个异常现象继续追踪相关页面、运行环境与用户行为。

## 访问分析

每次页面打开或 SPA 路由变化都会形成一条页面访问记录。平台可以据此提供：

- 今日与累计 PV、UV
- 访问量时间趋势
- 热门页面和来源页面
- 国家或地区分布
- 设备、浏览器、操作系统和屏幕环境
- 视口、语言、时区、网络类型等客户端信息

[了解访问分析 →](/features/analytics)

## 性能监控

SDK 使用浏览器 Performance API 观察加载、交互、视觉稳定性与主线程阻塞，自动提交：

- 核心体验：LCP、INP、CLS
- 首次反馈：FCP
- 服务端与网络：TTFB
- 主线程：TBT
- 页面生命周期：DOMContentLoaded、Load

[理解性能指标与优化方向 →](/features/performance)

## 错误监控

平台自动捕获四类常见线上失败：

- JavaScript 运行时异常
- 未处理的 Promise 拒绝
- Script、图片、样式等资源加载失败
- Fetch 与 XMLHttpRequest 网络错误和 HTTP 4xx/5xx

错误记录会带上页面上下文、堆栈和最近行为面包屑，帮助开发者判断“在哪里、什么环境、经过什么操作”发生了问题。

[了解错误采集边界 →](/features/errors)

## 业务事件

访问、性能和错误由 SDK 自动采集，适合描述通用体验；业务事件则用来描述产品目标，**不会自动产生**。平台无法猜测哪些动作对你的业务重要，只有你在代码中主动调用 `track()` 时才会记录：

```js
window.PulseWatch.track('checkout_completed', {
    order_type: 'subscription',
    plan: 'professional'
})
```

事件会附加访客、会话、页面访问、URL 和路径上下文，无需在每次调用时重复传入。

::tip
先从 3～5 个真正影响业务判断的关键事件开始，例如注册完成、购买完成和搜索无结果。事件越多不一定越有价值，清晰一致的命名更重要。
::

## 从发现到验证

一套有效的监控工作流通常是：

1. **发现**：趋势、错误或性能分布出现异常。
2. **定位**：收敛到页面、环境、版本或错误类型。
3. **评估**：结合访问量和业务事件判断影响面。
4. **修复**：针对资源、代码、接口或布局实施改动。
5. **验证**：对比改动前后的真实用户数据，而不是只看本地测试。
